# 大 QMT 共享内存通信设计

目标方案要求大 QMT 可以导入 mmap、与外部 Python 打开同名映射双向读写，并使用可靠同步机制；这些能力以独立探针的现场结果为准，当前尚未完成实测。用户于 2026-11-12 明确要求开始改造。QMT 代码最低兼容 Python 3.6，同时覆盖 3.12；外部 Worker 保持 Python 3.10+。

## 目标与边界

- 新增按账户选择的 mmap 后端，保留默认文件模式及现有 MCP 接口。
- QMT mmap 部署源码不导入 os、uuid、ctypes、multiprocessing，不使用文件、数据库或网络；使用注入的跨进程同步接口。
- 复用原 Adapter 的账户、Profile、授权、价格、数量和信用风控，不复制一套交易规则。
- SQLite 是执行许可的权威持久账本；共享内存只作为传输。原有外部配置、签名授权和文件队列可由 Worker 网关读取。
- 本次不连接券商、不实际报单，不把离线测试等同于目标环境验收。

## 已选方案和替代方案

采用 Windows 命名 mmap，在外部 Worker 增加网关，将现有命令及事件协议与共享内存连接。Python 3.8+ 的 shared_memory 不满足 3.6 下限；迁移 MiniQMT 需要另一个执行后端，用户已确认 mmap 可用，因此无需改变大 QMT 运行方式。

## 协议与安全

每个账户使用独立映射和预先部署的 HMAC 密钥。映射名不是凭据。生成的策略源码包含密钥，需按原消息密钥保护。Worker Token 不进入 QMT。

两个方向分别使用有确认的有界邮箱。帧包含协议版本、长度、序号、方向和 HMAC；接收侧完成持久化或安全处理后才确认。使用用户已验证的跨进程锁，不以 GIL、普通切片或 mmap.flush 代替同步。同步接口具体模块/签名已向用户询问，先完成与其无关的逻辑。

每次启动生成新的 Worker 和 Adapter 会话身份。控制帧包含配置、签名 Profile、本机授权、halt、执行日志和连接租约。控制过期、会话改变、消息溢出或校验失败时停止新增报单，旧执行许可不能跨会话使用。QMT 用短轮询推进状态，不阻塞等待外部持久化。

Worker 启动先用新序号替换未确认的旧控制帧，再恢复 SQLite。报单的最后边界在同一互斥量下确认控制帧仍为当前序号，并调用原生接口；Worker 接管与该边界串行化。已进入该边界的调用仍属于在途操作，不承诺撤回。旧会话签名回报先持久化再确认，旧执行请求进入持久审计隔离。

每帧按字节容量拆分批次；控制只携带当前许可完整额度历史及在途命令需要的执行记录。无关历史保留在 SQLite。若当前许可的完整额度历史超过容量，明确停止续租，不通过丢弃额度记录继续交易。

## 报单提交点与恢复

1. QMT 收到签名命令，执行原有账户/授权/行情风控，并请求执行许可。
2. Worker 对命令内容、账户、会话、有效期、当前模式与授权再次核对。
3. Worker 事务持久记录 PRE_SUBMIT 后才发布短期执行许可。
4. QMT 校验许可与当前控制状态，再次执行原风控，只调用一次 passorder。
5. QMT 返回结果；Worker 先持久记录和摄取回报，再确认接收。

PRE_SUBMIT 意味着可能已经报单，不表示柜台受理。许可丢失、任一方重启或报单前后崩溃均可能形成 SUBMIT_UNKNOWN；保守冻结、查询对账，不自动重新签发许可或重发。不能承诺 exactly-once。

## 验收

- 现有全部测试通过，默认文件部署内容及 Profile 保留行为不变。
- 双向传输、背压、显式确认、损坏帧、签名、大小和序号测试。
- SQLite 重启、重复/篡改命令、提交失败不发许可、UNKNOWN 恢复测试。
- 生成策略按 3.6 语法解析，在阻断 os/文件/网络/数据库导入的环境初始化及收发。
- 模拟 QMT 查询/报单接口验证无持久许可不报单、许可只执行一次、失联/过期/旧会话阻断。
- 真实 Windows 命名映射双进程测试；本机不存在的 Python 版本及券商环境明确列为待验收。

## 本次验证与现场接入

2026-11-12：Windows、Python 3.13.9 上全部 178 项测试通过。包括真实命名映射双进程交换、命名互斥量超时与遗弃、SQLite 提交/重启及模拟 QMT 全链路。已生成 wheel，并在隔离解释器中从其解压内容生成 mmap 部署脚本，确认资产完整及 Python 3.6 语法。

实际 Python 3.6/3.12 内置运行时及券商未执行现场验收。当前运行环境的限制范围与可用同步接口尚待 [能力探针](../../QMT-CAPABILITY-PROBE.zh-CN.md) 的实际结果；QMT 的 MMAP_LOCK_FACTORY 接入仍待该信息。默认外部实现是同名 Win32 mutex，其他同步机制须两端一并适配。
